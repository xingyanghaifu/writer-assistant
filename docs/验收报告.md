## 五、已知限制（诚实说明）

1. **选择器脆弱性**：四站点的 DOM 选择器基于当前页面结构。平台改版会导致失效。
   缓解：全部选择器集中在 `src/renderer/adapters/*.ts`，主进程不含站点细节，
   改版只需改一个文件；脚本带完整容错，失败时返回 `null` 而非抛异常。
2. **站点可用性波动**：不同地区/账号可能加载不同的前端版本，选择器需实机验证。
3. **分块策略为经验值**：`docs/chunking-notes.md` 中的长度上限会随平台调整而变化，
   代码中已留一倍余量，但极端长文本仍建议先手动分段。
4. **一致性检查为规则式**：基于角色表做规则匹配（状态/特征/形近字），
   不是语义理解，存在漏报可能；定位为"辅助提示"而非"保证正确"。
5. **无自动化 UI 测试**：冒烟测试覆盖主进程逻辑与首屏 DOM，
   交互流程（如拖拽、气泡菜单）需人工验证。
6. **未打包安装包**：`electron-builder.yml` 已配置完成（nsis/dmg、
   `forceCodeSigning: false`），但本轮未执行 `build:win` 产出安装程序。

### 打包验证结果（诚实记录）

尝试执行 `npx electron-builder --win`，**未能产出 NSIS 安装包**，原因如下：

| 步骤 | 结果 |
|---|---|
| 加载 `electron-builder.yml` | ✅ 配置解析正确（productName/appId/nsis 各项均生效） |
| 下载 7zip 工具链 | ✅ 通过 npmmirror 镜像成功 |
| 下载 NSIS 3.0.4.1 工具链 | ✅ 343 个文件，已缓存 |
| 下载 nsis-resources 3.4.1 | ✅ 22 个文件，已缓存 |
| 下载 Electron 发行版 | ❌ **卡在 0 字节**，`Timeout awaiting 'request' for 600000ms` |
| 生成 `win-unpacked` / NSIS 安装包 | ❌ 因上一步失败而未产出 |

**根因**：本环境的 GitHub Releases 下载不可用（curl 的 TLS 同样报
`SEC_E_NO_CREDENTIALS`）。经实测：

- `github.com/.../nsis-3.0.4.1.7z` → **TIMEOUT**
- `npmmirror.com/mirrors/electron-builder-binaries/...` → **可下载**（已验证 winCodeSign 5.6 MB 可完整获取）

设置 `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`
后，NSIS 与 winCodeSign 均成功下载，但 **Electron 自身的发行版 zip 仍走
`@electron/get`，未受该变量影响**，最终卡在 0 字节。

**这是环境网络限制，不是项目缺陷。** 在能访问 GitHub Releases 的网络下，
执行 `npm run build:win` 即可正常产出安装包。

### 适配器自检工具（应对"选择器脆弱"这一最大风险）

站点改版会让选择器失效，而**失败是静默的**（脚本容错返回 `null`）。
为把这一风险从"靠猜"变成"可观测"，新增了自检面板：

**位置**：设置 → 适配器自检

**能力**：
- 列出四个已注册适配器及其分块配置（模式 / 块大小）—— 无需读代码即可核对
- 逐个选择器实测命中数，**明确标出哪个选择器过期了**
- 显示登录态（`logged-in` / `logged-out` / `unknown`）
- 可选「写入测试」：向输入框填入测试串，验证插入链路是否可用（**不会发送**）

**修复路径**：右键目标元素 →「检查」→ 复制 class/id → 只改
`src/renderer/adapters/{站点}.ts` 顶部的选择器常量数组。
主进程不含任何站点细节，因此改版不会波及 `src/main/**`。
